# Ask

1. **Route.** Read the curated table at the top of `brain/routing.md`. If a row fits, read those notes first. For a kind of thing, start at its register in `brain/registers/`: people, organizations, projects, decisions, risks, glossary (terms), sources, open-questions.
2. **Walk.** Otherwise open the domain hub from `brain/index.md` and follow links: `[[links]]` in the text and relation fields (`projects`, `people`, `decisions`, `risks`, `owner`, ...). Read sources only when notes are not enough.
3. **Search last,** only if the path runs out.
4. **Stop early.** Read at most 6 notes unless the person asked for depth. Registers and hubs are cheap; whole sources are not. If more reading would help, answer with what you have and offer to go deeper.
5. **Answer.** Point first. Then one line: `From: <note titles>`. Mark anything not from notes as "(general knowledge)". If notes disagree, show both. Skip deprecated notes unless asked about history. For a decision say who, when and why; for a risk its severity, owner and mitigation.
6. **Improve the path.** If you had to search, or read more than five notes, add a row to the curated table in `brain/routing.md`: the kind of question, then the notes that answered it. If the answer had no home, offer to save it with **remember**.

Which notes you read is recorded automatically when you finish, so the brain learns what matters. Do not save the answer as a note unless the person asks or gave you new knowledge.
